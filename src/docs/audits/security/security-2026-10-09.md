# Auditoría de seguridad — Knit — 2026-10-09

Alcance: baseline del repo (rama de trabajo, sin commits de secretos), Supabase
(proyecto `knit` ref `wnzhbsitoamvcpzalqlq`), cliente Supabase en la PWA y
configuración de despliegue (Vercel). Método: inspección de árbol git + probes

## Veredicto global

**PASS con hallazgos ⚠️**

No hay fugas de secretos, RLS está activo y verificado en la base remota, y las
dependencias vulnerables son de tooling (dev/build), no de superficie expuesta.
Los hallazgos son MEDIO/BAJO y de endurecimiento.

## Hallazgos (por severidad)

### CRÍTICO
- Ninguno.

### ALTO
- Ninguno.

### MEDIO

- **M1 · Dependencia vulnerable (tooling) — `braces` <=3.0.3 (CVE GHSA-vfj7-8cjw-p6xm, high, DoS por stack exhaustion)**
  viene vía `shadcn > @shadcn/registry|ts-morph > fast-glob > micromatch > braces`.
  El paquete `shadcn` está declarado en `dependencies` (no en `devDependencies`),
  por lo que se instala en producción aunque solo sea CLI de scaffolding.
  Ubicación: `package.json`. Remediación: mover `shadcn` a `devDependencies` y/o
  `pnpm up braces` (corregido >=3.0.4). No es superficie de runtime.

- **M2 · Headers de seguridad HTTP ausentes.** No hay `next.config` headers ni
  `middleware.ts` ni `vercel.json`: sin CSP, `X-Frame-Options`/`frame-ancestors`,
  `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`. La app se
  despliega en Vercel como web pública. Ubicación: `next.config.ts` (vacío),
  ausencia de `middleware.ts`. Remediación: setear `headers()` en `next.config.ts`
  o un `middleware.ts` con CSP (ojo: el SW y el script de tema inline necesitan
  hash/nonce o `'unsafe-inline'` acotado).

### BAJO

- **B1 · `dangerouslySetInnerHTML` en `layout.tsx:53`.** Contenido es una constante
  estática (`themeScript`), sin input de usuario — riesgo nulo hoy, ya silenciado
  con `biome-ignore`. Se documenta por completitud; no requiere acción.

- **B2 · Persistencia de sesión en `localStorage` (`client.ts:14` `persistSession:true`).**
  Es el default de `supabase-js` en navegador. Cualquier XSS futuro podría leer el
  token. Mitigado porque `react-markdown@10` **no** usa `rehype-raw` (no renderiza
  HTML crudo del contenido de notas — sin vector XSS por notas). Mantener así.

- **B3 · Aprobación de buckets de Storage / MFA / Auth hardening no verificados.**
  No se auditó la config del dashboard de Supabase (email confirmation, rate
  limits, providers). Recomendación, no hallazgo.

- **B4 · Vercel no verificable.** El CLI está instalado pero **sin credenciales**
  (`vercel login` pendiente) y no existe `.vercel/`. No se pudo auditar
  variables de entorno del proyecto Vercel ni la config de build. Acción: correr
  `vercel login` y `vercel link`.

## Endpoints / Privilegios / Supabase

- **RLS: VERIFICADO EN VIVO ✅** en las 5 tablas (`folders`, `notes`, `tags`,
  `note_tags`, `tasks`). Probe anónimo sin sesión (anon key, sin JWT de usuario):
  - `SELECT /rest/v1/notes` → HTTP 200 `[]` (RLS filtra todo).
  - `INSERT` en `notes`, `folders`, `tags`, `note_tags`, `tasks` → HTTP 401
    `42501 new row violates row-level security policy`. RLS **activo** en todas.
- Migración `0001_init.sql` define `enable row level security` + policy
  `"own rows" for all using/with check (user_id = auth.uid())` en cada tabla.
- `supabase migration list --linked` → migración `0001` aplicada en remoto.
- No hay servicios de Storage ni tablas extra expuestas al rol `anon` (OpenAPI
  REST no devuelve tablas públicas adicionales).
- No hay API routes en Next (`src/app/**/route.ts` = 0); toda la lógica de sync es
  cliente → PostgREST. Superficie de servidor propia: mínima.
- Sync engine (`src/lib/sync/engine.ts`): push filtra por dueño
  (`row.ownerId === null || row.ownerId === userId`) y pull filtra `eq("user_id",
  userId)`; ambas capas quedan reforzadas por RLS. Validación de input delegada a
  Supabase Auth/PostgREST.

## Remediaciones aplicadas (esta sesión)

- [M1] `shadcn` movido a `devDependencies` en `package.json` (ya no se instala como
  runtime dependency).
- [overrides] `pnpm-workspace.yaml` añade `overrides.postcss-selector-parser: ">=7.1.6"`;
  no se aplica override para `braces>=3.0.4` porque la última publicada es
  `3.0.3` (seguimos tracking).
- [M2] Añadidos headers de seguridad + CSP en `next.config.ts` (X-Content-Type-Options,
  X-Frame-Options=DENY, Referrer-Policy, Permissions-Policy, HSTS, Content-Security-Policy
  con `connect-src` para Supabase). Incluye `unsafe-inline`/`unsafe-eval` solo en dev
  (por React/Turbopack).
- [SANITIZACIÓN] Creada `src/lib/sanitize.ts` (`sanitizeLine`, `sanitizeBody`) y
  aplicada a: `folders.create/rename`, `notes.update` (title/content), `tags.create/rename`,
  `tasks.create/update`, y emails normalizados (`lowercase+trim`) en `auth.ts`.
